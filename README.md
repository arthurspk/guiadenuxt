## :dart: O guia para alavancar a sua carreira

> Nuxt é o framework full-stack construído sobre o Vue.js: roteamento por arquivos, renderização no servidor (SSR), rotas de API embutidas (server routes), auto-imports e um sistema de módulos que cobre praticamente tudo que um projeto real precisa — SEO, imagens, conteúdo, autenticação e deploy. Mantido pela NuxtLabs e por uma comunidade ativa, o Nuxt é hoje a forma mais comum de construir aplicações Vue em produção. Este guia reúne roadmap, trilha de início, cursos gratuitos e pagos, documentação oficial, livros, canais, ferramentas do ecossistema, projetos práticos, comunidades e um capítulo dedicado a usar IA na prática com Nuxt — tudo verificado e organizado para quem já conhece o básico de Vue e quer sair do primeiro `npx nuxi init` até o deploy em produção.

## 🚀 Por onde começar

1. [Instalação e criação do primeiro projeto](https://nuxt.com/docs/getting-started/installation) — `npx nuxi@latest init` e a estrutura mínima de uma aplicação Nuxt.
2. [Auto-imports](https://nuxt.com/docs/guide/concepts/auto-imports) — O conceito mais importante do Nuxt: componentes, composables e utils ficam disponíveis sem `import` manual.
3. [Páginas e roteamento](https://nuxt.com/docs/getting-started/routing) — Como o roteamento por arquivos da pasta `pages/` funciona na prática.
4. [Views: app.vue, layouts e páginas](https://nuxt.com/docs/getting-started/views) — A anatomia de uma aplicação Nuxt: onde ficam layout, página e componentes.
5. [Buscando dados (Data Fetching)](https://nuxt.com/docs/getting-started/data-fetching) — `useFetch` e `useAsyncData`, os composables oficiais para buscar dados no servidor e no cliente.
6. [Servidor e rotas de API](https://nuxt.com/docs/getting-started/server) — Como criar endpoints de back-end dentro da pasta `server/`, sem precisar de um servidor separado.
7. [Gerenciamento de estado](https://nuxt.com/docs/getting-started/state-management) — `useState` para estado compartilhado entre componentes, e quando usar o Pinia.
8. [Deploy da aplicação](https://nuxt.com/docs/getting-started/deployment) — Opções de deploy: estático, servidor Node, Edge/serverless e a NuxtHub.

## 🤖 IA na prática

Nuxt e IA se encontram em duas frentes: usar assistentes de IA para escrever a aplicação mais rápido, e usar o próprio ecossistema Nuxt para dar contexto a esses assistentes — o Nuxt foi um dos primeiros frameworks a ganhar um módulo dedicado de servidor MCP.

**Para aprender**

- Peça para um assistente de IA **explicar a diferença entre `useFetch` e `useAsyncData`** em um trecho de código seu — é a dúvida mais comum de quem começa a buscar dados no Nuxt.
- Cole um erro de hidratação (`Hydration mismatch`) e peça a causa mais provável — geralmente é HTML inválido ou uso de `window`/`Date`/`Math.random()` fora de um hook de cliente.
- Peça para **converter um componente de Options API para Composition API com `<script setup>`**, explicando cada mudança feita.
- Peça exercícios práticos sobre um conceito específico (rotas de servidor, middleware, `useState`) e depois valide rodando o código.

**Para trabalhar**

- Use o [GitHub Copilot](https://github.com/features/copilot), o [Cursor](https://cursor.com/) ou o [Claude Code](https://code.claude.com/docs/en/overview) para gerar rotas de servidor, tipar composables e escrever testes com o Vitest.
- Instale o [nuxt-mcp](https://github.com/antfu/nuxt-mcp) em modo de desenvolvimento: ele expõe a estrutura de rotas, componentes e composables do seu projeto para o assistente de IA, reduzindo sugestões genéricas ou desatualizadas.
- Depois de aceitar uma sugestão, rode o build (`nuxi build`) e o lint. Um composable chamado fora do `<script setup>` ou um `import` manual de algo auto-importável é sinal de sugestão mal pensada.
- Revise sempre chamadas de API sugeridas por IA: confirme se elas deveriam rodar no servidor (`server/api`) ou no cliente, para não vazar chaves ou repetir requisições desnecessárias.

**Limites e boas práticas**

- IA tende a **misturar sintaxe do Vue 2/Nuxt 2 com Vue 3/Nuxt 3+** (ex.: `this.$nuxt`, `asyncData` de página, `context` do Nuxt 2). Confirme sempre contra a [documentação oficial](https://nuxt.com/docs) da versão que você usa.
- Ela também erra com frequência o **auto-import**: se a IA sugerir `import { ref } from 'vue'` ou `import { useFetch } from '#app'` em um projeto Nuxt, na maioria dos casos isso é desnecessário e pode até quebrar o build.
- Cuidado com código que mistura contexto de servidor e cliente (ex.: usar `window` fora de `onMounted` ou sem checar `import.meta.client`).
- Não cole variáveis de ambiente, chaves de API ou dados de clientes em ferramentas de IA sem a política da sua empresa.
- Entenda o que você aceita: em entrevista técnica e em produção, o código é seu.
